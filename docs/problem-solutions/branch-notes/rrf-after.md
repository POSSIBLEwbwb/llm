# 修复后版本：按 chunkId 做业务级融合

这个分支用于模拟问题修复后的状态。

## 版本特点

修复后不再完全依赖默认内容对象判断相等，而是把检索结果包装成项目自己的内容对象。

判断两个结果是不是同一个知识片段时，以业务唯一标识 `chunkId` 为准。

## 修复逻辑

核心变化有三点：

- 按 `chunkId` 去重，避免同一片段重复占用 Top-K。
- 按 RRF 公式累加同一片段在不同检索器中的排名分数。
- 按累加后的融合分数倒序排序，再交给 Reranker 做精排。

这样一来，如果同一个片段同时被向量检索和关键词检索召回，它不会重复出现，而是会得到更高的融合分数。

## 修复价值

这次优化提升的不是单个模型能力，而是检索链路的工程质量：

- Top-K 结果更干净。
- 多路召回优势能被正确利用。
- 给大模型的上下文重复率更低。
- 后续生成答案更稳定。

## 面试讲法

可以这样讲：

> 我们没有改 RRF 算法本身，而是修正了内容相等性的业务定义。默认逻辑不知道同一个 `chunkId` 应该算同一个片段，所以会重复和乱序。修复后我们按 `chunkId` 做去重和分数累加，再按融合分数排序，最后交给 Reranker 精排。这个改动让 Top-K 的信息密度明显更高。
