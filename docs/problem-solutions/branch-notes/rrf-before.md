# 修复前版本：默认 RRF 融合逻辑

这个分支用于模拟问题修复前的状态。

## 版本特点

修复前直接复用默认的 RRF 聚合能力，把多个检索器返回的内容直接交给融合器处理。

当向量检索、全文检索、混合检索同时召回同一个知识片段时，系统依赖默认内容对象判断“这是不是同一条内容”。

## 存在的问题

默认内容对象并不知道项目里的业务唯一标识是 `chunkId`，它更偏向按对象本身和元数据判断是否相等。

所以同一个知识片段从不同检索器返回时，虽然业务上是同一个片段，但在融合逻辑里可能会被当成多条内容。

这会带来三个后果：

- 相同片段重复出现在 Top-K 结果里。
- 同一片段在多个检索器中的排名优势没有被累加。
- 融合后的排序不稳定，最终上下文质量下降。

## 面试讲法

可以这样讲：

> 修复前我们直接用默认 RRF 做多路检索融合，但后来发现同一个 chunk 会重复出现。根因是默认内容对象不理解我们的业务唯一键，不能按 `chunkId` 合并结果，所以 RRF 分数没有正确累加，排序也会被影响。
